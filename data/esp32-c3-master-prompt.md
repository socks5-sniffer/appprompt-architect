### 2. Project Context
**Project Name:** `esp32-c3`
**Application Type:** Interactive Web Application

**Description:**
The `esp32-c3` web application will serve as an interactive platform for developers to explore, modify, and test ESP32-C3 GPIO pins with various electrical components. The application will feature:
*   A comprehensive list of common electrical components.
*   For each component, provide relevant C++ code snippets compatible with the Arduino IDE for ESP32-C3.
*   Detailed wiring instructions and diagrams for connecting components to the ESP32-C3.
*   Functionality for users to search and filter components.
*   The ability for users to upload and manage their own custom components, including descriptions, pin configurations, C++ code, wiring instructions, and associated images.
*   An activity logging/audit trail system to track user actions, especially related to component creation and modification.

**Target Audience:** Developers, hobbyists, and students interested in ESP32-C3 microcontroller development. The interface should be technical, clear, and provide practical code examples.

**Core Features to Implement:**
*   **Dark/Light Mode Toggle:** Seamless switching between themes.
*   **Search & Filtering:** Efficiently find components by name, category, or keywords.
*   **File Upload & Storage:** For user-submitted custom component images and potentially documentation.
*   **Activity Logging / Audit Trails:** Record significant user actions (e.g., component creation, updates, deletions).

### 6. Security & Performance

#### Security Requirements
*   **OWASP Top 10 Compliance:** Proactively address and mitigate common web application vulnerabilities (e.g., Injection, Broken Authentication, XSS, SSRF, Security Misconfiguration, Insecure Deserialization, etc.).
*   **JWT Authentication:** Implement robust JWT authentication with secure token storage (e.g., HTTP-only cookies for refresh tokens), proper expiration, and refresh token rotation strategies.
*   **Role-Based Access Control (RBAC):** Define clear roles (e.g., `guest`, `user`, `admin`) and enforce granular permissions for all backend API endpoints and sensitive frontend features.
*   **Data Encryption:**
    *   **At Rest:** Ensure sensitive data in PostgreSQL (e.g., `password_hash`, potentially custom component details if deemed highly sensitive) is encrypted. Rely on managed service encryption or implement application-level encryption where necessary.
    *   **In Transit:** Enforce HTTPS for all communication between the frontend and backend.
*   **Rate Limiting:** Implement rate limiting on critical endpoints (e.g., login, registration, password reset, component creation) to prevent brute-force attacks and abuse.
*   **Input Validation:** Strict server-side input validation using Zod (or Joi) on *all* incoming data from the client. Frontend validation is for UX, not security.
*   **CORS:** Properly configure Cross-Origin Resource Sharing (CORS) policies to restrict API access to the frontend origin.
*   **Password Hashing:** Store user passwords using a strong, modern, and computationally expensive hashing algorithm (e.g., `bcrypt`).
*   **Helmet.js:** Use the `helmet` middleware for Express.js to set various security-related HTTP headers.
*   **Sanitization:** Sanitize all user-generated content (especially C++ code snippets and descriptions) to prevent XSS attacks when rendered on the frontend.

#### Performance Requirements
*   **Database Optimization:** Implement efficient database indexing, optimize SQL queries, and utilize connection pooling.
*   **Backend Optimization:** Design efficient API endpoints, minimize payload sizes, and consider caching strategies for frequently accessed static data (e.g., common component lists).
*   **Frontend Optimization:**
    *   Implement lazy loading for routes and components.
    *   Optimize images and other assets.
    *   Utilize `React.memo`, `useCallback`, and `useMemo` to prevent unnecessary re-renders.
    *   Implement virtualized lists for displaying large sets of components if necessary.
    *   Minimize JavaScript bundle size and optimize asset delivery.
*   **Scalability:** Design the backend to be stateless where possible to facilitate horizontal scaling.
